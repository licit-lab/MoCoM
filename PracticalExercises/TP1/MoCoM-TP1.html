🚦 SUMO Traffic Simulation Tutorial

Complete Step-by-Step Guide to Urban Traffic Simulation with SUMO

📋 What is SUMO?

SUMO (Simulation of Urban MObility) is an open-source, highly portable, microscopic and continuous multi-modal traffic simulation package designed to handle large networks. It allows modeling and simulating traffic flows, traffic lights, vehicle interactions, and analyzing traffic patterns.

Typical Traffic Project Workflow:

  1. Install SUMO on your operating system (Windows, Linux, or macOS)
  2. Create or Import Network using NetEdit or convert OSM files
  3. Understand OSM & NetConvert for map conversions and network preparation
  4. Define Routes & Flows for vehicles (e.g., 50 vehicles/hour)
  5. Configure Traffic Lights and control logic
  6. Run Simulation with SUMO-GUI or command line
  7. Control with Python TraCI for dynamic scenarios
  8. Post-Process Results - analyze queues, wait times, emissions

1️⃣ Installation Guide

▼

Choose your operating system and follow the installation instructions. Each platform has a video tutorial to guide you through the process.

Windows Installation

  • Download the latest SUMO installer from eclipse.org/sumo
  • Run the installer (.exe file) and follow the setup wizard
  • Set the SUMO_HOME environment variable to the installation directory
  • Add SUMO's bin folder to your system PATH
  • Verify installation by opening Command Prompt and typing: sumo --version

Linux Installation

  • Add SUMO repository to your system: 
    sudo add-apt-repository ppa:sumo/stable
sudo apt-get update
  • Install SUMO and all tools: 
    sudo apt-get install sumo sumo-tools sumo-doc
  • Set environment variable in ~/.bashrc: 
    export SUMO_HOME="/usr/share/sumo"
  • Reload bash configuration: source ~/.bashrc
  • Verify installation: sumo --version

macOS Installation

  • Install Homebrew if not already installed: 
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
  • Install SUMO using Homebrew: 
    brew tap dlr-ts/sumo
brew install sumo
  • Set environment variable in ~/.zshrc or ~/.bash_profile: 
    export SUMO_HOME="/usr/local/opt/sumo/share/sumo"
  • Reload configuration: source ~/.zshrc
  • Verify installation: sumo --version

2️⃣ Creating Networks with NetEdit

▼

NetEdit is SUMO's visual network editor that allows you to create road networks, junctions, traffic lights, and more with a graphical interface.

Launching NetEdit

netedit

Step-by-Step Network Creation:

  • Create Edges (Roads): Click the "Edge" mode button, then click on the canvas to place nodes. Edges are automatically created between nodes.
  • Configure Edge Properties: Right-click an edge to set number of lanes, speed limits, and lane types.
  • Add Junctions: Junctions are automatically created where edges meet. You can modify junction types (priority, traffic light, etc.).
  • Set Traffic Lights: Right-click a junction and select "Convert to traffic light junction".
  • Save Network: File → Save Network As → mynetwork.net.xml
💡 Tip: Use the "Select" mode to move nodes and modify the network layout. Use "Inspect" mode to view and edit detailed properties.

3️⃣ Understanding OSM Files & NetConvert Tool

▼

What is an OSM File?

OSM (OpenStreetMap) files are XML-based files containing geographical data from OpenStreetMap - a free, editable map of the world created by volunteers. OSM files contain:

  • Nodes: Points with latitude/longitude coordinates (intersections, endpoints)
  • Ways: Ordered lists of nodes representing roads, paths, boundaries
  • Relations: Logical connections between nodes and ways (bus routes, turn restrictions)
  • Tags: Metadata describing features (road type, speed limit, name)

How to Download OSM Files:

  • OpenStreetMap.org:
    • Go to openstreetmap.org
    • Navigate to your desired area
    • Click "Export" at the top
    • Select the area and click "Export" to download .osm file

NetConvert Tool - Converting Map Formats

NetConvert is SUMO's powerful conversion tool that transforms various map formats into SUMO's native .net.xml format. It can also convert SUMO networks to other formats.

Converting OSM to SUMO Network (.net.xml):

# Basic conversion
netconvert --osm-files map.osm -o map.net.xml

# Advanced conversion with road network improvements
netconvert --osm-files map.osm -o map.net.xml \
  --geometry.remove \
  --ramps.guess \
  --junctions.join \
  --tls.guess-signals

NetConvert Options Explained:

  • --geometry.remove - Removes unnecessary geometry points for cleaner networks
  • --ramps.guess - Automatically detects and configures highway ramps
  • --junctions.join - Merges nearby junctions into single intersections
  • --tls.guess-signals - Automatically places traffic lights at appropriate junctions

What is XODR (OpenDRIVE)?

XODR (OpenDRIVE) is an open standard format for describing road networks, primarily used in autonomous driving simulation and testing. It provides highly detailed geometric and semantic road descriptions including:

  • Precise road geometry with reference lines
  • Lane layouts and markings
  • Road signals and signs
  • Objects along the road (barriers, poles)

Converting SUMO Network to XODR:

# Convert .net.xml to OpenDRIVE format
netconvert -s map.net.xml --opendrive-output map.xodr

Converting XODR to SUMO Network:

# Convert OpenDRIVE to SUMO format
netconvert --opendrive-files map.xodr -o map.net.xml
💡 Why use XODR? OpenDRIVE format is essential for integrating SUMO with autonomous vehicle simulators like CARLA, ensuring compatibility across different simulation platforms.

4️⃣ Creating Routes & Traffic Flows

▼

Understanding Routes

Routes define the paths that vehicles take through the network. You need to create a rou.xml file that specifies vehicle types, routes, and flows.

Basic Route File Structure (routes.rou.xml):

<routes>
    <!-- Define vehicle type -->
    <vType id="car" accel="2.6" decel="4.5" sigma="0.5" length="5" maxSpeed="50"/>
    
    <!-- Define a route -->
    <route id="route1" edges="edge1 edge2 edge3 edge4"/>
    
    <!-- Define traffic flow -->
    <flow id="flow1" type="car" route="route1" begin="0" end="3600" 
          vehsPerHour="600" departLane="best" departSpeed="max"/>
    
    <!-- Alternative: Individual vehicles -->
    <vehicle id="veh1" type="car" route="route1" depart="0"/>
</routes>

Understanding Traffic Flows - The vehsPerHour Parameter

The vehsPerHour parameter controls how many vehicles enter the network per hour. This is crucial for simulating different traffic conditions:

Example 1: Light Traffic (50 vehicles/hour)

Perfect for off-peak hours or residential areas:

<routes>
    <vType id="car" accel="2.6" decel="4.5" sigma="0.5" length="5" maxSpeed="50"/>
    <route id="route_light" edges="edge1 edge2 edge3"/>
    
    <!-- 50 vehicles per hour = 1 vehicle every 72 seconds -->
    <flow id="flow_light" type="car" route="route_light" 
          begin="0" end="3600" vehsPerHour="50"/>
</routes>

Example 2: Moderate Traffic (200 vehicles/hour)

Typical daytime traffic on urban roads:

<routes>
    <vType id="car" accel="2.6" decel="4.5" sigma="0.5" length="5" maxSpeed="50"/>
    <route id="route_moderate" edges="edge1 edge2 edge3 edge4"/>
    
    <!-- 200 vehicles per hour = 1 vehicle every 18 seconds -->
    <flow id="flow_moderate" type="car" route="route_moderate" 
          begin="0" end="3600" vehsPerHour="200"/>
</routes>

Example 3: Heavy Traffic (500 vehicles/hour)

Rush hour conditions on main arterial roads:

<routes>
    <vType id="car" accel="2.6" decel="4.5" sigma="0.5" length="5" maxSpeed="50"/>
    <route id="route_heavy" edges="edge1 edge2 edge3 edge4 edge5"/>
    
    <!-- 500 vehicles per hour = 1 vehicle every 7.2 seconds -->
    <flow id="flow_heavy" type="car" route="route_heavy" 
          begin="0" end="3600" vehsPerHour="500"/>
</routes>

Multiple Flows with Different Rates:

<routes>
    <vType id="car" accel="2.6" decel="4.5" sigma="0.5" length="5" maxSpeed="50"/>
    <vType id="truck" accel="1.5" decel="3.5" sigma="0.3" length="12" maxSpeed="35"/>
    
    <route id="route_north" edges="n1 n2 n3 n4"/>
    <route id="route_south" edges="s1 s2 s3 s4"/>
    
    <!-- Main road: 50 cars per hour -->
    <flow id="cars_north" type="car" route="route_north" 
          begin="0" end="3600" vehsPerHour="50"/>
    
    <!-- Side road: 20 cars per hour -->
    <flow id="cars_south" type="car" route="route_south" 
          begin="0" end="3600" vehsPerHour="20"/>
    
    <!-- Trucks: 10 per hour on main road -->
    <flow id="trucks_north" type="truck" route="route_north" 
          begin="0" end="3600" vehsPerHour="10"/>
</routes>

Creating Routes in NetEdit:

  • Open your network in NetEdit
  • Switch to "Demand" mode (traffic light icon in toolbar)
  • Create vehicle types with specific parameters
  • Define routes by selecting edges in sequence
  • Set flows with departure rates using vehsPerHour parameter
  • Save as routes.rou.xml
💡 Pro Tip: Use vehsPerHour for continuous traffic flow. The value directly represents vehicles per hour: 50 = light traffic, 200 = moderate, 500+ = heavy congestion.

5️⃣ Traffic Light Configuration

▼

Traffic lights are crucial for managing intersection flow. SUMO allows you to define custom phases and timing for each traffic light.

Traffic Light Phases

Each phase defines which lanes have green, yellow, or red signals. Phases are defined in a separate file or inline in the network.

Traffic Light Definition (tllogic.add.xml):

<additional>
    <tlLogic id="junction1" type="static" programID="1" offset="0">
        <!-- Phase 1: North-South Green -->
        <phase duration="30" state="GGrrrrGGrrrr"/>
        
        <!-- Phase 2: North-South Yellow -->
        <phase duration="3" state="yyrrrryyrrrr"/>
        
        <!-- Phase 3: East-West Green -->
        <phase duration="30" state="rrGGrrrrGGrr"/>
        
        <!-- Phase 4: East-West Yellow -->
        <phase duration="3" state="rryyrrrryyrr"/>
    </tlLogic>
</additional>

State String Explanation:

  • G = Green (go)
  • g = Green without priority
  • y = Yellow (prepare to stop)
  • r = Red (stop)

Rush Hour Traffic Light Design:

For rush hour scenarios, adjust phase durations to accommodate higher traffic volumes on main routes:

<!-- Rush Hour Configuration -->
<tlLogic id="junction1" type="static" programID="rush_hour">
    <!-- Longer green time for main road (45 seconds) -->
    <phase duration="45" state="GGrrrrGGrrrr"/>
    <phase duration="3" state="yyrrrryyrrrr"/>
    
    <!-- Shorter green time for side road (20 seconds) -->
    <phase duration="20" state="rrGGrrrrGGrr"/>
    <phase duration="3" state="rryyrrrryyrr"/>
</tlLogic>

6️⃣ Python TraCI Control

▼

TraCI (Traffic Control Interface) allows you to control the simulation dynamically using Python scripts. You can modify traffic lights, vehicles, and gather real-time data.

Basic TraCI Setup:

import traci
import os
import sys

# Set SUMO_HOME environment variable
if 'SUMO_HOME' in os.environ:
    tools = os.path.join(os.environ['SUMO_HOME'], 'tools')
    sys.path.append(tools)
else:
    sys.exit("Please declare environment variable 'SUMO_HOME'")

# Start SUMO with configuration
sumoBinary = "sumo-gui"  # or "sumo" for command line
sumoCmd = [sumoBinary, "-c", "simulation.sumocfg"]

traci.start(sumoCmd)

# Run simulation for 1000 steps
step = 0
while step < 1000:
    traci.simulationStep()
    step += 1

traci.close()

Keyboard Control Example:

import traci
import keyboard  # pip install keyboard
import time

traci.start(["sumo-gui", "-c", "config.sumocfg"])

# Traffic light control variables
current_phase = 0
junction_id = "junction1"

def change_traffic_light():
    global current_phase
    current_phase = (current_phase + 1) % 4  # Cycle through 4 phases
    traci.trafficlight.setPhase(junction_id, current_phase)
    print(f"Changed to phase {current_phase}")

print("Press SPACE to change traffic light phase")
print("Press ESC to exit simulation")

step = 0
while step < 3600:
    traci.simulationStep()
    
    # Check for keyboard input
    if keyboard.is_pressed('space'):
        change_traffic_light()
        time.sleep(0.3)  # Debounce
    
    if keyboard.is_pressed('esc'):
        break
    
    step += 1

traci.close()

Collecting Simulation Data:

# Get vehicle information
vehicle_ids = traci.vehicle.getIDList()

for veh_id in vehicle_ids:

# Get traffic light information
tl_state = traci.trafficlight.getRedYellowGreenState(junction_id)
print(f"Traffic light state: {tl_state}")

7️⃣ Running the Simulation

▼

Create Configuration File (simulation.sumocfg):

<configuration>
    <input>
        <net-file value="mynetwork.net.xml"/>
        <route-files value="routes.rou.xml"/>
        <additional-files value="tllogic.add.xml"/>
    </input>
    
    <time>
        <begin value="0"/>
        <end value="3600"/>
    </time>
    
    <processing>
        <time-to-teleport value="-1"/>
    </processing>
</configuration>

Running Options:

  • GUI Mode: Visual simulation with controls 
    sumo-gui -c simulation.sumocfg
  • Command Line Mode: Faster execution without graphics 
    sumo -c simulation.sumocfg
  • With Python TraCI: Dynamic control during simulation 
    python simulation_control.py

8️⃣ Post-Processing & Analysis

▼

After running the simulation, analyze the results to understand traffic patterns, identify bottlenecks, and evaluate environmental impact.

Output Files Configuration:

<output>
    <!-- Vehicle trip information -->
    <tripinfo-output value="tripinfo.xml"/>
    
    <!-- Queue length at edges -->
    <queue-output value="queue.xml"/>
    
    <!-- Emissions data -->
    <emission-output value="emissions.xml"/>
    
    <!-- Summary statistics -->
    <summary-output value="summary.xml"/>
</output>

Key Metrics to Analyze:

  • Queue Length: Number of vehicles waiting at intersections
  • Waiting Time: Total time vehicles spend stopped or moving slowly
  • Travel Time: Time taken to complete journeys
  • Emissions: CO2, NOx, PM, and fuel consumption
  • Throughput: Number of vehicles completing trips

Python Analysis Script:

import xml.etree.ElementTree as ET
import pandas as pd
import matplotlib.pyplot as plt

# Parse trip information
tree = ET.parse('tripinfo.xml')
root = tree.getroot()

trip_data = []
for trip in root.findall('tripinfo'):
    trip_data.append({
        'id': trip.get('id'),
        'duration': float(trip.get('duration')),
        'waitingTime': float(trip.get('waitingTime')),
        'timeLoss': float(trip.get('timeLoss'))
    })

df = pd.DataFrame(trip_data)

# Calculate statistics
print(f"Average Duration: {df['duration'].mean():.2f}s")
print(f"Average Waiting Time: {df['waitingTime'].mean():.2f}s")
print(f"Average Time Loss: {df['timeLoss'].mean():.2f}s")

# Visualize waiting times
plt.figure(figsize=(10, 6))
plt.hist(df['waitingTime'], bins=30, edgecolor='black')
plt.xlabel('Waiting Time (seconds)')
plt.ylabel('Number of Vehicles')
plt.title('Distribution of Vehicle Waiting Times')
plt.savefig('waiting_time_histogram.png')
plt.show()

Environmental Impact Analysis:

# Parse emissions data
emissions_tree = ET.parse('emissions.xml')
emissions_root = emissions_tree.getroot()

total_co2 = 0
total_nox = 0
total_fuel = 0

for timestep in emissions_root.findall('timestep'):
    for vehicle in timestep.findall('vehicle'):
        total_co2 += float(vehicle.get('CO2', 0))
        total_nox += float(vehicle.get('NOx', 0))
        total_fuel += float(vehicle.get('fuel', 0))

print(f"Total CO2 Emissions: {total_co2/1000:.2f} kg")
print(f"Total NOx Emissions: {total_nox:.2f} g")
print(f"Total Fuel Consumption: {total_fuel:.2f} ml")
